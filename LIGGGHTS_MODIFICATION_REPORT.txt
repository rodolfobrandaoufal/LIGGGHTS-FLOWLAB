3. Memory Layout And SoA Transition

3.1 Atom-level SoA fields

Files:

  src/atom.h
  src/atom.cpp

Changes:

  - Added sphere-oriented SoA pointers at the Atom level:

      pos_x, pos_y, pos_z
      vel_x, vel_y, vel_z
      force_x, force_y, force_z
      omega_x, omega_y, omega_z
      torque_x, torque_y, torque_z

  - Initialized these pointers to NULL in Atom construction.
  - Destroyed these arrays in Atom cleanup.
  - Kept AoS arrays such as x, v, f available for compatibility with the broader
    LIGGGHTS infrastructure.

Rationale:

  - The full LIGGGHTS data model is deeply AoS-compatible. The implemented
    transition uses a sphere-specific SoA fast path while preserving legacy MPI,
    dump, fix, and atom-style compatibility.

3.2 Aligned memory support

  - Added AlignedAllocator and ParticleSoA helper container.
  - ParticleSoA stores position, velocity, force, mass/type scratch fields in
    contiguous aligned vectors.

Performance intent:

  - Improve cache-line utilization.

5.3 Generalized adhesion model

File:

  src/cohesion_model_generalized_adhesion.h

Changes:

  - Added new cohesion model:

      cohesion generalized_adhesion

  - Registers and uses:

      adhesionEnergy peratomtypepair

  - Computes adhesive force from a generic overlap quantity:

      deltan = sidata.deltan
      A_eff = pi * reff * deltan
      F_coh = -adhesionEnergy[itype][jtype] * A_eff

  - Avoids Hertz-specific contact-area reconstruction.
  - Designed to be compatible with Hooke, Hertz, and nonspherical/superquadric
    overlap sources as long as sidata.deltan is provided by the active surface
    model.

12. Known Caveats And Risks
===============================================================================

  - The SoA migration is not a total replacement of Atom::x, Atom::v, Atom::f.
    It is a sphere fast path plus compatibility bridge. Full global SoA would
    require larger MPI, restart, dump, fix, compute, and package-wide redesign.

  - Many generated object files exist under src/Obj_hdf5mpi and src/Obj_serial.
    These are build artifacts, not source-level design changes.

  - The build emits many warnings from existing code and template instantiations.
    They should be separated into a warning-cleanup pass before production use.

  - OpenMPI emitted:

      opal_ifinit: socket() failed with errno=1

    during compilation. The build still completed, but this environment issue
    should be checked before running large MPI jobs.

  - HDF5 output requires the hdf5mpi build or another build configured with
    -DLIGGGHTS_HDF5 and parallel HDF5 libraries.

  - SJKR remains Hertz/sphere-area based. Use generalized_adhesion for Hooke or
    shape-agnostic adhesive behavior.

  - The current report is based on local git status/diff and source inspection.
    It is not a substitute for a full physics validation campaign.
